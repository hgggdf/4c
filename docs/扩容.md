# 管线数据扩容 — OpenClaw 爬取与入库规范

> **本文档的定位**：在现有 OpenClaw 数据包格式基础上，新增 `pipeline_drug` 类型。下文第一节给出包含所有已有类型 + 新增类型的**完整 manifest.json**，后续章节（第二节起）仅针对新增的 `pipeline_drug` 类型展开说明，已有类型（company / financial / announcement / research_report / news / macro）的 JSONL 格式不变。

---

## 一、数据包结构

### 目录布局（完整版，含所有已有类型 + 新增类型）

```
data/incoming/{batch_id}/
├── manifest.json
├── company/
│   └── company_records.jsonl
├── financial/
│   └── financial_records.jsonl
├── announcement/
│   └── announcement_records.jsonl
├── research_report/
│   └── research_report_records.jsonl
├── news/
│   └── news_records.jsonl
├── macro/
│   └── macro_records.jsonl
└── pipeline/                              ← 新增
    └── pipeline_drug_records.jsonl        ← 新增
```

### manifest.json（完整版）

```json
{
  "batch_id": "20260527_full_001",
  "status": "ready",
  "data_types": [
    "company",
    "financial",
    "announcement",
    "research_report",
    "news",
    "macro",
    "pipeline_drug"
  ],
  "files": {
    "company": "company/company_records.jsonl",
    "financial": "financial/financial_records.jsonl",
    "announcement": "announcement/announcement_records.jsonl",
    "research_report": "research_report/research_report_records.jsonl",
    "news": "news/news_records.jsonl",
    "macro": "macro/macro_records.jsonl",
    "pipeline_drug": "pipeline/pipeline_drug_records.jsonl"
  }
}
```

> **不需要每次都包含所有类型。** 如果某次只爬取了管线数据，manifest 可以只写：

```json
{
  "batch_id": "20260527_pipeline_001",
  "status": "ready",
  "data_types": ["pipeline_drug"],
  "files": {
    "pipeline_drug": "pipeline/pipeline_drug_records.jsonl"
  }
}
```

### manifest 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `batch_id` | string | 唯一批次标识，建议格式 `YYYYMMDD_[类型]_NNN` |
| `status` | string | 必须为 `"ready"` 才会被 `process_batch()` 处理 |
| `data_types` | string[] | 本批次包含的数据类型列表 |
| `files` | object | 每种类型对应的 JSONL 文件相对路径 |

**data_types 合法值（完整列表）**：

| 值 | 说明 | 入库顺序 |
|---|---|---|
| `company` | 公司基础信息 | 1 |
| `financial` | 财务数据 | 2 |
| `announcement` | 公告 | 3 |
| `research_report` | 研报 | 4 |
| `news` | 新闻 | 5 |
| `macro` | 宏观指标 | 6 |
| **`pipeline_drug`** | **管线药品（新增）** | **7** |

入库按上述顺序执行，`pipeline_drug` 排在最后是因为它依赖 `company` 表的外键（`stock_code` 必须先存在）。

## 二、JSONL 单条格式

每行一个 JSON 对象，UTF-8 编码（**不带 BOM**）。

```json
{
  "stock_code": "600276",
  "drug_name": "SHR-A1811",
  "canonical_drug_name": "SHR-A1811",
  "aliases": ["SHR-A1811"],
  "indication": "HER2阳性乳腺癌",
  "indication_norm": "HER2阳性乳腺癌",
  "therapeutic_area": "肿瘤",
  "trial_phase": "phase3",
  "trial_phase_raw": "III期临床",
  "route_of_administration": "injection",
  "source_type": "cde_clinical_trial",
  "source_url": "https://www.chinadrugtrials.org.cn/...",
  "source_table": "announcement_hot",
  "source_id": 456,
  "source_uid": "announcement:456",
  "evidence_text": "恒瑞医药2025年年报研发管线表披露SHR-A1811处于III期临床。",
  "confidence_score": 0.88
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `stock_code` | string | ✅ | A 股代码，必须已存在于 `company` 表 |
| `drug_name` | string | ✅ | 药品名称（原始来源中的表述） |
| `canonical_drug_name` | string | 建议 | 归一名称（代号优先 → 通用名兜底）。缺省时取 `drug_name` |
| `aliases` | string[] | 建议 | 所有已知别名（代号、INN、中文通用名、商品名） |
| `indication` | string | 建议 | 适应症原始表述 |
| `indication_norm` | string | 建议 | 适应症标准化表述（用于去重） |
| `therapeutic_area` | string | 建议 | 治疗领域，见下方枚举 |
| `trial_phase` | string | ✅ | 标准化阶段，见下方枚举 |
| `trial_phase_raw` | string | 建议 | 原始阶段表述（保留溯源） |
| `route_of_administration` | string | 可选 | 给药方式：oral / injection / topical / inhalation 等 |
| `source_type` | string | 建议 | 来源类型，见下方枚举 |
| `source_url` | string | 建议 | 来源页面 URL |
| `source_table` | string | 可选 | 关联的内部表名（如 `announcement_hot`） |
| `source_id` | int | 可选 | 关联的内部记录 ID |
| `source_uid` | string | 可选 | 关联的内部 dedup_key 或 uid |
| `evidence_text` | string | ✅ | 支撑该条事实的原文摘录（≥20 字） |
| `confidence_score` | float | 建议 | 置信度 [0, 1]，缺省 0.70 |

## 三、枚举值

### trial_phase（试验阶段）

| 标准值 | 对应原始表述 |
|---|---|
| `preclinical` | 临床前、IND |
| `phase1` | I期、1期、一期、Phase I |
| `phase1_2` | I/II期、1/2期 |
| `phase2` | II期、2期、二期、Phase II |
| `phase2_3` | II/III期、2/3期 |
| `phase3` | III期、3期、三期、Phase III |
| `nda` | NDA、申报上市、上市申请、已申报 |
| `nda_rejected` | NDA被拒、上市申请被拒 |
| `approved` | 已上市、已获批、获批上市、批准上市 |
| `terminated` | 终止、已终止 |
| `withdrawn` | 撤回、已撤回、暂停 |
| `unknown` | 无法识别（兜底） |

> 系统会自动标准化，OpenClaw 可以直接传原始表述到 `trial_phase`，后端会做映射。但建议 OpenClaw 尽量传标准值以减少歧义。

### therapeutic_area（治疗领域）

| 标准值 | 对应关键词 |
|---|---|
| `oncology` | 肿瘤、癌 |
| `cardiovascular` | 心血管、心脏 |
| `metabolic` | 代谢、糖尿 |
| `immunology` | 免疫、自免 |
| `infection` | 感染、病毒 |
| `cns` | 神经、中枢 |
| `rare_disease` | 罕见病、孤儿药 |
| `vaccine` | 疫苗 |
| `ophthalmology` | 眼科 |
| `other` | 其他（兜底） |

### source_type（来源类型）

| 值 | 说明 |
|---|---|
| `cde_clinical_trial` | CDE 药物临床试验登记平台 |
| `annual_report` | 年报研发管线表 |
| `prospectus` | 招股书 |
| `announcement` | 公告（临床试验进展、获批等） |
| `analyst_report` | 分析师研报 |
| `company_website` | 公司官网 |
| `hkex_filing` | 港交所披露易 |
| `user_input` | 人工录入 |

## 四、去重规则

去重键 = `sha256(stock_code + canonical_drug_name_norm + indication_norm)`

- **不含 trial_phase**：同一药品阶段推进时只更新同一行，不会创建新行。
- 已存在时的更新规则：
  - **phase 单调推进**：只允许升级（preclinical → phase1 → ... → approved），不允许降级。`terminated` / `withdrawn` 是唯一允许的"回退"。
  - **confidence 单调**：新 confidence < 旧 confidence 时，不覆盖 drug_name / indication / phase 等关键字段。
  - **aliases 合并**：新别名追加到已有列表，不覆盖。
  - **evidence_text / source_url 始终刷新**：追踪最新看到这条事实的出处。

## 五、爬取来源与策略

### 来源 1：CDE 药物临床试验登记与信息公示平台

| 项目 | 内容 |
|---|---|
| 网址 | https://www.chinadrugtrials.org.cn/ |
| 入口 | 首页 → 试验公示和查询 → 高级查询 |
| 可获取字段 | drug_name, indication, trial_phase, route_of_administration, 申办者 |
| 爬取策略 | 按申办者名称（公司全称）搜索；每日增量抓取"最近更新"列表 |
| 频率 | 每日一次，增量 |
| 注意事项 | 平台有反爬限制，需控制请求频率（≥2s/请求）；部分试验有多个适应症需拆行 |

### 来源 2：巨潮资讯网（深交所法定披露）

| 项目 | 内容 |
|---|---|
| 网址 | https://www.cninfo.com.cn/ |
| 入口 | 信息披露 → 上市公司公告 → 按股票代码 + 公告类型筛选 |
| 可获取字段 | 年报/半年报中的"研发管线表"（PDF 表格抽取） |

## 七、药品名称归一策略

同一药品在不同来源中名称不同：

| 来源 | 可能出现的名称 |
|---|---|
| CDE 平台 | SHR-1210（研发代号） |
| 年报 | 卡瑞利珠单抗（通用名） |
| 商业报道 | 艾瑞卡（商品名） |
| 英文文献 | Camrelizumab（INN） |

**归一规则**：

1. `canonical_drug_name` 优先使用**研发代号**（如 SHR-1210），因为代号在整个生命周期中最稳定。
2. 如果没有代号，使用**中文通用名**。
3. 所有曾出现过的名称都放入 `aliases` 数组。
4. 去重键使用 `canonical_drug_name` 计算，确保同一药品不会因为名称变体而产生多行。

## 八、置信度评分参考

| 来源 | 建议 confidence_score |
|---|---|
| CDE 平台直接查询 | 0.90 - 0.95 |
| 年报/招股书管线表 | 0.85 - 0.92 |
| 公司公告（临床进展） | 0.80 - 0.90 |
| 分析师研报 | 0.70 - 0.80 |
| 新闻报道 | 0.60 - 0.75 |
| LLM 推断（无直接证据） | 0.40 - 0.60 |

> 置信度影响更新守卫：低置信度来源不会覆盖高置信度来源的关键字段。

## 九、在线接口格式（实时推送）

除批量 JSONL 外，OpenClaw 也可通过 HTTP 接口实时推送：

```
POST /api/pipeline/upsert-drugs
Content-Type: application/json

{
  "items": [
    {
      "stock_code": "600276",
      "drug_name": "SHR-XXXX",
      "canonical_drug_name": "SHR-XXXX",
      "aliases": [],
      "indication": "非小细胞肺癌",
      "indication_norm": "非小细胞肺癌",
      "therapeutic_area": "oncology",
      "trial_phase": "phase3",
      "trial_phase_raw": "III期临床",
      "route_of_administration": "injection",
      "source_type": "cde_clinical_trial",
      "source_url": "https://www.chinadrugtrials.org.cn/...",
      "evidence_text": "CDE登记平台披露该药处于III期临床。",
      "confidence_score": 0.88
    }
  ]
}
```

响应：

```json
{
  "created": 1,
  "updated": 0,
  "warnings": []
}
```

## 十、注意事项

1. **编码**：所有文件必须是 UTF-8 无 BOM。带 BOM 的文件会导致 manifest 解析失败。
2. **stock_code 前置条件**：目标公司必须先存在于 `company` 表。如果是新公司，需要在同一批次中先包含 `company` 类型数据。
3. **evidence_text 不能为空**：这是数据质量的底线保障，至少 20 字的原文摘录。
4. **不要传 `expected_approval_year`**：预计获批年份由 AI Agent 在 rNPV 计算时动态推算，不存入事实表。
5. **terminated / withdrawn 要及时更新**：终止的药品如果不标记，rNPV 会继续按活跃管线计算，产生严重高估。
6. **反爬合规**：CDE 平台和交易所网站有访问频率限制，建议单源请求间隔 ≥ 2 秒，使用合理的 User-Agent，不要并发爬取。
