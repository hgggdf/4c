# 数据入库手册（OpenClaw → 关系库 + 向量库）

> 本手册指导 OpenClaw 把爬取到的数据正确组织成批次包，让 `import_batch.py` 自动完成入库与向量回填。覆盖 7 种数据类型：`company / financial / announcement / research_report / news / macro / pipeline_drug`。
>
> **AI 助手 / 运维**：先看 [运维命令速查](#零运维命令速查)；OpenClaw 写数据看 [批次目录结构](#二批次目录结构) 起。

---

## 〇、运维命令速查

> 所有命令都在 `backend/` 目录下执行，并且都用项目自带的虚拟环境：
> `.venv/Scripts/python.exe <script>`（Windows）或 `.venv/bin/python <script>`（Linux/Mac）。
>
> 下面用 `python` 简写，按需替换。

### 1. 入关系库（OpenClaw 批次 → MySQL）

| 操作 | 命令 |
|---|---|
| **入单个批次** | `python import_batch.py data/incoming/{batch_id}` |
| **入所有 incoming 批次** | `python import_batch.py --all` |

行为：
- 按 `manifest.json` 的 `data_types` 字段，按强制顺序入库（company → financial → announcement → research_report → news → macro → pipeline_drug）
- 每条记录单独 commit（一条失败不会回滚前面成功的）
- 成功后批次目录从 `data/incoming/{batch_id}/` 移到 `data/processed/{batch_id}/`，生成 `import_report.json`
- 全军覆没的批次会移到 `data/failed/{batch_id}/`
- 入库后源行 `vector_status='pending'`，等待向量库回填

不会触碰向量库。

### 2. 向量库 — 增量回填（每天用这个）

| 操作 | 命令 |
|---|---|
| **只回填新增 / 已更新数据** | `python scripts/bulk_backfill.py --incremental` |

行为：
- 扫描所有源表，只处理 `vector_status IN ('pending', 'failed')` 的行
- 对没有 `vector_status` 字段的表（`company / financial_notes`），用 `vector_document_index.created_at` vs 源表 `updated_at` 反查需要补的行
- 批量 embed（256 chunks/批）→ 批量 chroma upsert → 批量 `vector_document_index` 写入
- 处理后源行标 `vector_status='success'`，空 content 标 `skipped_empty`
- **scheduler 每日同步自动调用这个**（`backend/app/scheduler.py:138`）
- 没新数据时会幂等空跑（约 2 秒）

不删旧数据，不重写已 success 的行。

### 3. 向量库 — 全量重建（运维场景）

| 操作 | 命令 |
|---|---|
| **清空所有 chroma collection 后全量重建** | `python scripts/bulk_backfill.py` |

行为：
- 按 doc_type 逐个清空 chroma collection 和 `vector_document_index` 中对应行
- 然后扫源表所有行，批量重建（不看 `vector_status`）
- 全部行最终标 `vector_status='success'`

**何时用**：
- 修改了 chunk 切分逻辑 / embedding 模型
- chroma 数据损坏或想从零重建
- 大量历史数据没建过索引

3000 chunks 大约 2-3 分钟（CPU embedding 是瓶颈）。

### 4. 向量库 — 单 collection 重建（精修）

| 操作 | 命令 |
|---|---|
| **只重建公告 collection** | `python scripts/rebuild_announcement_collection.py` |
| **只删空公告 collection（不回填）** | `python scripts/rebuild_announcement_collection.py --skip-backfill` |
| **只重建研报 collection** | `python scripts/rebuild_research_report_collection.py` |
| **只删空研报 collection（不回填）** | `python scripts/rebuild_research_report_collection.py --skip-backfill` |

**何时用**：某个 collection 单独损坏或需要单独迁移，不想动其它 collection。

### 5. 向量库 — 一致性自检

| 操作 | 命令 |
|---|---|
| **抽样检查向量库 vs 关系库一致性** | `python scripts/verify_vector_index.py --sample-size 10` |

5 项验证：数量一致性 / 内容溯源 / Metadata 完整性 / 集合隔离 / 检索闭环。任何一项失败都会非零退出。

### 6. 数据库初始化

### 9. 典型组合流程

#### A) OpenClaw 推了一批新数据（每日增量场景）
```bash
cd backend
python import_batch.py data/incoming/20260527_daily_001
python scripts/bulk_backfill.py --incremental
```
之后可以选做：
```bash
python scripts/verify_vector_index.py --sample-size 5    # 抽样验证
```

#### B) 全量重建向量库（运维场景）
```bash
cd backend
python scripts/bulk_backfill.py                # 注意：会先清空所有 chroma collection
python scripts/verify_vector_index.py --sample-size 10
```

#### C) 数据库被清空后从零开始
```bash
cd backend
python -c "from app.bootstrap import init_application_database; init_application_database()"
python import_batch.py --all                   # 入所有 incoming 批次
python scripts/bulk_backfill.py                # 全量重建向量库
```

#### D) 怀疑某个 collection 出问题
```bash
cd backend
python scripts/verify_vector_index.py --sample-size 20  # 先看哪类有问题
python scripts/rebuild_announcement_collection.py       # 只重建有问题的那类
```

## 一、整体流程

```
OpenClaw 爬取 / 抽取
        ↓
data/incoming/{batch_id}/
  ├── manifest.json
  ├── {data_type}/{data_type}_records.jsonl
  └── ...
        ↓
python import_batch.py data/incoming/{batch_id}     ← 关系库入库
        ↓
关系库行 vector_status = 'pending'
        ↓
scheduler 每日同步 / 手动调用：
python scripts/bulk_backfill.py --incremental       ← 向量库增量回填
        ↓
chroma collection + vector_document_index 同步更新
        ↓
关系库行 vector_status = 'success'
        ↓
批次目录从 incoming/ 移动到 processed/
```

OpenClaw **只需要负责前两步**：把数据写成 manifest + JSONL，放到 `data/incoming/{batch_id}/`。后续的关系库入库、向量回填、状态更新都由 import_batch / scheduler 自动完成。这条不一定要遵守，openclaw也可以选择爬完数据直接手动入库（数据库和向量库）

## 二、批次目录结构

```
data/incoming/{batch_id}/
├── manifest.json                                  ← 必须
├── company/
│   └── company_records.jsonl
├── financial/
│   └── financial_records.jsonl
├── announcement/
│   └── announcement_records.jsonl
├── research_report/
│   └── research_report_records.jsonl
├── news/
│   └── news_records.jsonl
├── macro/
│   └── macro_records.jsonl
└── pipeline/
    └── pipeline_drug_records.jsonl
```

**只产出有数据的子目录即可**，没爬到的类型不放对应目录、manifest 里也不列。

### batch_id 命名规范

`YYYYMMDD_<场景>_NNN`，例如：
- `20260527_daily_001` — 每日全量
- `20260527_pipeline_001` — 仅管线
- `20260527_announcement_002` — 当日第二个公告补抓批次

**唯一性**：批次入库后会被移到 `data/processed/{batch_id}/`，不要复用同名 batch_id。

## 三、manifest.json

### 完整版示例

```json
{
  "batch_id": "20260527_daily_001",
  "status": "ready",
  "data_types": [
    "company",
    "financial",
    "announcement",
    "research_report",
    "news",
    "macro",
    "pipeline_drug"
  ],
  "files": {
    "company": "company/company_records.jsonl",
    "financial": "financial/financial_records.jsonl",
    "announcement": "announcement/announcement_records.jsonl",
    "research_report": "research_report/research_report_records.jsonl",
    "news": "news/news_records.jsonl",
    "macro": "macro/macro_records.jsonl",
    "pipeline_drug": "pipeline/pipeline_drug_records.jsonl"
  }
}
```

### 仅入一类的示例

```json
{
  "batch_id": "20260527_pipeline_001",
  "status": "ready",
  "data_types": ["pipeline_drug"],
  "files": {
    "pipeline_drug": "pipeline/pipeline_drug_records.jsonl"
  }
}
```

### 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| `batch_id` | ✅ | 唯一批次标识；处理后会作为 processed/ 下的子目录名 |
| `status` | ✅ | 必须是 `"ready"`，否则 import_batch 会跳过整个批次 |
| `data_types` | ✅ | 字符串数组；只列本批次实际有数据的类型 |
| `files` | ✅ | 每种类型对应的 JSONL 相对路径 |

**可选**字段（不影响入库，但 OpenClaw 内部追踪有用）：

```json
{
  "created_at": "2026-05-27T1530",
  "stock_codes": ["000538", "600276"],
  "stock_count": 2,
  "stats": { "company": 2, "announcement": 671, ... }
}
```

后端 `process_batch()` 只读 `batch_id / status / data_types / files` 四个，多余字段被忽略。

### 入库执行顺序

不论 manifest 里 `data_types` 顺序如何，import_batch 强制按以下顺序执行（满足外键依赖）：

```
1. company  →  2. financial  →  3. announcement  →  4. research_report
   →  5. news  →  6. macro  →  7. pipeline_drug
```

**外键约束**：`financial / announcement / research_report / pipeline_drug` 都依赖 `company.stock_code`。如果同批次新增公司 + 该公司的子数据，公司必须出现在 company JSONL 里。

---

## 四、JSONL 文件格式约定

- 每行一个独立 JSON 对象（标准 NDJSON）
- **UTF-8 编码，不带 BOM**（manifest.json 同样要求无 BOM）
- 一行一条记录，不允许跨行 JSON
- 空行允许（被解析时跳过）
- 单条解析失败不会中断批次（会计入 `import_report.json` 的 errors）

---

## 五、各 data_type 字段约定

> 标记说明：✅ 必填（OpenClaw 必须提供，不允许 null/空字符串）/ ⚪ 可选（OpenClaw 可不提供，留空入库）/ 📝 字段说明

### 5.1 company（公司）

文件：`company/company_records.jsonl`，目标表：`company`

```json
{
  "stock_code": "600276",
  "stock_name": "恒瑞医药",
  "full_name": "江苏恒瑞医药股份有限公司",
  "exchange": "SH",
  "industry_level1": "医药生物",
  "industry_level2": "化学制药",
  "industry_code": "GICS_3520",
  "listing_date": "2000-10-18",
  "business_summary": "公司主营医药制造业...",
  "core_products_json": ["卡瑞利珠单抗", "瑞维鲁胺"],
  "main_segments_json": {"创新药": 0.65, "仿制药": 0.35}
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `stock_code` | string(16) | ✅ | 主键，A 股 6 位数字 |
| `stock_name` | string(64) | ✅ | 中文简称 |
| `full_name` | string(128) | ✅ | 全称 |
| `exchange` | string(16) | ✅ | `SH` / `SZ` / `BJ` / `HK` |
| `industry_level1` | string(64) | ⚪ | 默认 `"医药生物"` |
| `industry_level2` | string(64) | ✅ | 二级行业 |
| `industry_code` | string(32) | ⚪ | 行业代码（必须先存在于 `industry_master`，否则会自动创建） |
| `listing_date` | date | ⚪ | `YYYY-MM-DD` |
| `business_summary` | text | ✅ | **会被向量化进 `company_profile_chunks`**，建议 100-2000 字 |
| `core_products_json` | json | ⚪ | 核心产品列表 |
| `main_segments_json` | json | ⚪ | 业务分部占比 |

**去重键**：`stock_code`（主键）。已存在时会按字段更新。

### 5.2 financial（财务 + 行情）

文件：`financial/financial_records.jsonl`，目标表：`financial_hot`

financial 表同时承载**两类数据**，通过 `report_type` 区分，字段必填规则**完全不同**：

| report_type | 含义 | 核心必填 | 不需要填 |
|---|---|---|---|
| `annual` / `q1` / `q2` / `q3` | 财务报告 | 财务指标字段 | 行情字段（trade_date / open_price / close_price 等） |
| **`daily`** | **日行情快照** | **行情字段** | **财务指标字段（revenue / net_profit 等）** |

| — | — | — | — | — |

| `total_liabilities` | decimal(20,2) | ✅ | ⚪ | 总负债 |
| `debt_ratio` | decimal(10,6) | ⚪ | ⚪ | 自动计算：total_liabilities / total_assets |
| `operating_cashflow` | decimal(20,2) | ✅ | ⚪ | 经营活动现金流净额 |
| `investing_cashflow` | decimal(20,2) | ✅ | ⚪ | 投资活动现金流净额 |
| `financing_cashflow` | decimal(20,2) | ✅ | ⚪ | 筹资活动现金流净额 |
| — | — | — | — | — |
| `trade_date` | date | ⚪ | ✅ | 交易日期，格式 `YYYY-MM-DD` |
| `open_price` | decimal(12,4) | ⚪ | ✅ | 开盘价 |

| `high_price` | decimal(12,4) | ⚪ | ✅ | 最高价 |

| `title` | string(255) | ✅ | 公告标题（≤ 255 字符） |

| `summary_text` | text | ✅ | 摘要，用于检索快照展示 |
| `key_fields_json` | json | ⚪ | 结构化字段（药品审批/临床试验/集采/监管风险等） |

**去重键**：`(stock_code, normalized_title, publish_date)`。`title` 在 hash 前会去 `000001:` / `sh600276-` 等前缀并 casefold。

### 5.7 pipeline_drug（药品研发管线）

文件：`pipeline/pipeline_drug_records.jsonl`，目标表：`pipeline_drugs`

详细规范见 `docs/扩容.md`。核心字段速览：

```json
{
  "stock_code": "600276",
  "drug_name": "SHR-A1811",
  "canonical_drug_name": "SHR-A1811",
  "aliases": ["SHR-A1811"],
  "indication": "HER2阳性乳腺癌",
  "indication_norm": "HER2阳性乳腺癌",
  "therapeutic_area": "肿瘤",
  "trial_phase": "phase3",
  "trial_phase_raw": "III期临床",
  "route_of_administration": "injection",
  "source_type": "annual_report",
  "source_url": "https://www.cninfo.com.cn/...",
  "evidence_text": "恒瑞医药2025年年报研发管线表披露SHR-A1811处于III期临床。",
  "confidence_score": 0.88
}
```

**关键约束**：
- `stock_code`、`drug_name`、`trial_phase`、`evidence_text` 必填（evidence_text ≥ 20 字）
- `trial_phase` 标准值：`preclinical / phase1 / phase1_2 / phase2 / phase2_3 / phase3 / nda / nda_rejected / approved / terminated / withdrawn / unknown`
- ⚠️ **不要** 把 `IND 获批` 标成 `nda`（那是 NDA 提交，是后期），应映射为 `preclinical` 或 `phase1`
- 阶段降级会被守卫拒绝（除非新值是 `terminated` / `withdrawn`）
- 低置信度新条目不会覆盖高置信度旧条目的关键字段

**去重键**：`sha256(stock_code + canonical_drug_name + indication_norm)`。**不含 trial_phase**，这样阶段推进时只更新同一行，不会创建新行。

## 六、去重与更新语义

### 6.1 dedup_key 用途

每条记录入库前会自动计算 `dedup_key`（已规范化哈希），存进表的 `dedup_key` 列，并作为 UNIQUE 索引。

| 类型 | dedup_key 组成（标准化后） |
|---|---|
| financial | `stock_code + report_type + report_date` |
| announcement | `stock_code + publish_date + normalized_title` |
| research_report | `scope_type + scope_key + publish_date + report_org + normalized_title` |
| news | 优先 `normalized(source_url)`；否则 `source_name + publish_time + normalized_title` |
| pipeline_drug | `stock_code + canonical_drug_name + indication_norm` |
| macro | `(indicator_name, period)` 直接做 UNIQUE，不另算 hash |
| company | `stock_code` 做 PK，不另算 hash |

### 6.2 已存在时的更新规则

- **company**：按字段覆盖（除空字段外）
- **financial / announcement / research_report / news**：覆盖更新业务字段，保留原 `*_uid`、`created_at`
- **macro**：覆盖更新
- **pipeline_drug**：守卫式更新——
  - phase 单调推进（除非 terminated/withdrawn）
  - confidence 单调（低置信度不覆盖关键字段）
  - aliases 合并而非覆盖
  - source / evidence 始终刷新

### 6.3 OpenClaw 重发同一 batch_id 会怎样

不要这么做。`processed/` 下已存在同名 batch_id 时，重发会失败。如果确实要重抓，请用新的 batch_id（如加 `_v2` 后缀）。

## 七、向量化字段速览

OpenClaw 不需要做向量化，但应该清楚**哪些字段会被向量化**，确保它们的内容质量。

| 数据类型 | 入向量库的字段 | Chroma collection |
|---|---|---|
| company | `business_summary` + `market_position` + `management_summary`（拼接） | `company_profile_chunks` |
| announcement | `content` 优先，否则 `summary_text` | `announcement_chunks` |
| research_report | `content` 优先，否则 `summary_text` | `research_report_chunks` |
| news | `content` | `news_chunks` |
| pipeline_drug | 由 `drug_name + indication + therapeutic_area + trial_phase + evidence_text + ...` 自动拼成结构化文本 | `pipeline_drug_chunks` |
| financial | `note_text` 字段（如果有） | `financial_note_chunks` |
| macro | （不向量化） | — |

**chunk_size = 500，overlap = 50**。所以单条记录的可向量化文本越长，向量库里的 chunk 数越多。

向量化的 metadata 包含：`stock_code / industry_code / publish_date / source_url / title / source_table / source_pk / source_uid / doc_type` 等，这些字段在源 JSONL 里准确填好，向量检索的过滤效果会更好。

## 八、运行入库

OpenClaw 写完批次后，调下面命令（可由后端 cron 自动调，也可手动）：

```bash
cd backend
python import_batch.py data/incoming/{batch_id}
```

或入所有 incoming 批次：

```bash
python import_batch.py --all
```

成功后批次会被移到 `data/processed/{batch_id}/`，并生成 `import_report.json`：

```json
{
  "batch_id": "20260527_daily_001",
  "status": "success",
  "finished_at": "2026-05-27T01:30:14",
  "success_count": 1587,
  "failed_count": 0,
  "errors": []
}
```

`status` 取值：
- `success`：全部成功
- `partial`：部分成功（具体看 `errors` 列表）
- `failed`：全军覆没（批次会移到 `data/failed/`）

## 九、向量库回填

**OpenClaw 不需要触发**——后端 scheduler 每日同步时自动调用：

```python
# backend/app/scheduler.py
from scripts.bulk_backfill import run_bulk_backfill
result = run_bulk_backfill(incremental=True)
```

逻辑：
- 扫描 `vector_status IN ('pending', 'failed')` 的源行
- 批量 embed + 批量 chroma upsert
- 同步 `vector_document_index`
- 处理完把对应行标 `vector_status='success'`
- 空 content 的行标 `skipped_empty`，下次不会再扫到

**手动触发全量重建**（运维场景，OpenClaw 一般不用）：

```bash
python scripts/bulk_backfill.py
```

## 十、常见错误与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `WinError 10013` 启动失败 | 8001 端口被旧进程占用 | 杀掉占用进程或换端口 |
| `Data too long for column 'content'` | 单条 content > 65 KB | content 列已升级为 LONGTEXT，实际上没有数据库层面的截断限制；但 OpenClaw 必须在写出前按 10000 字规则处理（> 10000 字先总结再截） |
| 输入 N 条但只有 X 条入库（X < N） | 之前的事务管理 bug，已修复（每条单独 commit） | 升级到最新 import_batch.py |
| `IntegrityError: foreign key constraint fails` | 财务/公告等数据的 `stock_code` 在 company 表里不存在 | 在同批次 manifest 里加 `company` 类型，先入公司 |
| manifest 解析失败 | 文件带 UTF-8 BOM | 用 UTF-8 (无 BOM) 写入 |
| dedup_key 唯一约束冲突 | 同批次内有逻辑重复条目 | 由 OpenClaw 自己先去重；或者把重复的合并成同一条 |
| 公告入库成功但前端"暂无事件" | content 太长 → 历史 bug | 已修复，现在 content 支持 LONGTEXT |
| `pipeline_drug` 报"未找到 company: XXX" | pipeline 里的 stock_code 没有在 company 表 | 在批次里加上对应 company 记录 |

## 十一、最终检查清单（OpenClaw 自检）

发批次前，请逐项确认：

- [ ] `manifest.json` 是 UTF-8 无 BOM
- [ ] 所有 JSONL 文件 UTF-8 无 BOM，每行一条标准 JSON
- [ ] manifest 里 `data_types` 与实际目录、文件一一对应
- [ ] `batch_id` 与目录名一致，且唯一
- [ ] 涉及外键的子数据（financial / announcement / report / pipeline_drug）的 `stock_code` 已在 company 表中存在，或本批次同时入了 company
- [ ] 必填字段全部非空（`stock_code / title / publish_date / drug_name / evidence_text` 等）
- [ ] `pipeline_drug` 的 `trial_phase` 是合法枚举值之一
- [ ] `pipeline_drug` 的 `IND 获批` 不要标成 `nda`
- [ ] 长文本（announcement.content / research_report.content / news.content）**≤ 10000 字全文；> 10000 字先总结再截到 10000 字以内**
- [ ] PDF/HTML 附件如有，文件名与 JSONL 里 `local_file` 字段一致
